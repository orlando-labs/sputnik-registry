# Выпуск пакетов и переход на короткие имена, 2026-10-22

Основной hub: `https://registry.sputnik-lang.online`. Все канонические пакеты
принадлежат namespace `slowpilot`; короткие root names назначаются оператором.
Импорт сохраняет namespace автора: например, установка `sqlite3@0.1.0`
предоставляет `slowpilot.sqlite3`, а `torch@0.1.2` — `slowpilot.torch.*`.
Старое имя `sputniktorch` удалено без совместимости: canonical ref и root alias
возвращают HTTP 404, пять неиспользуемых архивов удалены из CAS.

## Матрица

Чистые Sputnik-модули portable. Source и bytecode опубликованы там, где
представление поддерживается; mixed присутствует только при реальном сочетании
source и bytecode. Макросы ORM/Orbit сохраняются в source. SQLite имеет один
macro provider module, поэтому отдельный bytecode-вариант не создаётся.

Native SQLite/Plot/PyCall/RbCall собраны на macOS arm64 >=26.0 и Linux x86-64
GNU >=2.36. Варианты различают source/prebuilt adapter и source/bytecode modules;
SQLite предоставляет только source modules. Оптимизация C/C++ адаптеров — `-O3`.
`system-io` имеет шесть macOS arm64 вариантов (два adapter × три module formats).
Linux system-io пока не выпускается: standalone native SDK там не проверен.

Torch: macOS CPU/MPS prebuilt+runtime, macOS source без bundle и Linux
CUDA 13.0 prebuilt+runtime. Все требуют LibTorch 2.14.0 с проверенными ABI/build
identity. Source требует внешние matching runtime/SDK, Gloo и C++20 toolchain.
MPS проверяется с `PYTORCH_ENABLE_MPS_FALLBACK=0`; CUDA — на RTX 3090/4090.

PyCall/RbCall сохраняют интерпретатор и стандартную библиотеку внешними.
Проверенные версии: CPython 3.14.6 / CRuby 4.0.5 на macOS и CPython 3.11.2 /
CRuby 3.1.2 на Linux. Требования фиксируют точные version, ABI и native build
hash; consumer создаёт provider descriptors из подходящей установки.
На macOS interpreter/provider/cache должны находиться на одной файловой системе,
чтобы native-модули интерпретатора использовали ту же runtime image.
System IO также требует matching внешний Sputnik runtime и SDK; его private
SDK snapshot в пакет не включается. Рецепты находятся в `release/` репозиториев.

## Проверки и границы

Пакеты проверяются после установки архивов в изолированные stores, без sibling
module paths. SQLite: 35 core, 18 pool и backup; Plot: 32; ORM: 30 core и 17 pool;
Orbit: core, contract и ORM integration; UI: CSV/Markdown; progressbar: реальный
fixture. Foreign bridges проверяют runtime imports, callbacks и lifetime,
invalid handles, VM и самостоятельные native executables. System IO проверяет
файлы/пакеты/digest/process, symlink/traversal rejection, VM и native.
Locks проверяют точный variant, archive SHA-256 и origin.

Native-проверки используют `--require-full-native`. SQLite, Plot, ORM, foreign
bridges и System IO прошли соответствующие standalone native tests. Notebook UI
и progressbar используют notebook runtime API и проверены в VM. Полный native
HTTP-клиентский selftest Orbit пока требует шести SDK fallback code objects
(`start_request`); VM conformance проходит. Это ограничение не скрывается
ослаблением native gate или compiler optimization.

Потребителю нужен текущий SDK с поддержкой scoped foreign imports, installed
macro providers и native variants. Правки SDK находятся в текущем workspace;
отдельный SDK release в рамках публикации пакетов не создавался.

```sh
sputnik pkg versions torch
sputnik pkg variants torch@0.1.2
sputnik pkg install sqlite3 --version 0.1.0 --allow-native
sputnik pkg install torch --version 0.1.2 --backend mps --bundle runtime \
  --allow-native --allow-native-large
```

Root alias меняет выбор package reference при установке. Он не меняет имена
модулей или автора в lock-файле. Явный `--variant` и `--build-from-source`
сохраняются; технические requirements действуют при любом выборе варианта.
